# 操作ガイドのデザイン方針

対象は `torabotsuki-xs.html`。操作中に必要な情報を参照するリファレンスとして設計する。

## 情報の置き場所

| 調べたいこと | 掲載する場所 |
| --- | --- |
| キー単体の短押し・長押し | 選択したレイヤーの配列図 |
| 複数キーの同時押し | 全幅の配列図の下段にあるコンボ一覧 |
| キーを保持して右ボールを動かす操作 | 配列直下のジェスチャー3枚 |
| 左パッドと右ボールの役割・速度 | ポインティング操作のセクション |
| 接続・切断・登録削除の手順 | 接続セクション |
| ホストの入力ソース・ショートカット設定 | OS設定セクション |
| 判定時間・設定ファイル・書き込み後の検証 | ページ末尾の開発者メモ内の折りたたみ |

配列・コンボ・右ボールは同じ参照領域に置く。ジェスチャーの内容を別のセレクターで隠さず、タブ切替・ウィンドウ配置・スクロールを常時見せる。各カードは「保持するキー＋ボール」「方向→結果」の同じ順序にする。レイヤー選択では該当カードを強調する。

配列図は常に上段の全幅。下段ではジェスチャーとコンボを2列に並べる。スマートフォン幅では配列→ジェスチャー→コンボの順に並べる。コンボ一覧に独立したスクロール領域を作らない。狭い画面で配列図だけ横スクロールを許す。

## 参照したガイドと適用

- [NN/g: Proximity Principle in Visual Design](https://www.nngroup.com/articles/gestalt-proximity/): 関連情報を近接させる。幅によって配置が変わっても、ジェスチャーとコンボの関係が崩れないようにする。
- [NN/g: Recognition and Recall](https://www.nngroup.com/articles/recognition-and-recall/): 別の表示で覚えた内容を思い出す負荷を減らす。3種類のジェスチャーと保持キーを常設する。
- [GOV.UK: Details](https://design-system.service.gov.uk/components/details/): 多くの利用者が必要とする情報を折りたたみに隠さない。保持キー・方向・結果は常設する。日常の補足はOS設定内、判定時間やQA手順は末尾の開発者メモへ分ける。
- [Diátaxis: Reference](https://diataxis.fr/reference/): 参照情報を一貫したパターンで提示する。操作早見と、接続の手順・OS側の設定を分ける。

## 確認項目

- Windows／Macの全レイヤーで、配列・有効なコンボ・3枚のジェスチャーが表示される。
- コンボを選ぶと押す位置が配列図で強調され、ジェスチャーは隠れない。
- 全配列のコンボから該当レイヤーへ移動できる。
- Macのタブ切替は右Ctrl、Windowsは左Ctrlと表示する。
- 1440／1280／1024／800／390px幅で、ページ全体が横にはみ出さない。
- デスクトップ・中間幅とも、配列図の下でジェスチャーとコンボの上端が揃う。
- 日常セクションと動的なコンボ解説に、ms単位の判定・設定ファイルパス・実機QA文言が現れない。
- Bluetoothの接続・切断は独立した表、登録削除は独立した警告ボックスに置く。
- 開発者メモは初期状態で閉じ、印刷時は全レイヤーの配列図以外を非表示にする。
- 印刷では配列・ジェスチャー・コンボが欠落せず、閉じた補足説明は省く。
- 日英トグルの提案例 `RC(SPACE)` と、現在のファームウェアの割り当てを区別する。
