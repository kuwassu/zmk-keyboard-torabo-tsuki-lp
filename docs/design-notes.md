# 操作ガイドのデザイン方針

対象は `torabotsuki-xs.html`、`manual.css`、`manual.js`、`trackpad-scroll.svg`。Apple Human Interface Guidelinesの考え方を、オフラインでも使えるWebの操作リファレンスへ適用する。

## 視線の流れと情報階層

OS → レイヤー → キー配列 ⇔ コンボ → ジェスチャー

- **Clarity**：操作と結果を「保持するキー ＋ ボール → 結果」で示す。キーの主ラベルと長押しラベルを分け、H／J／Kの軸選択は同じ構造のバッジにする。
- **Deference**：大きい配列図を主役にする。枠線を重ねず、ページ・サーフェス・補助サーフェスの色と余白でまとまりを作る。シャドウは選択中セグメントとキーのハイライトに限定する。
- **Depth**：選択・一時プレビュー・固定を異なる状態として表す。レイヤー切替は短いフェード、コンボ位置は同じSVG内の色と輪郭で変化させる。補足情報は折りたたみから必要なときだけ開く。

デスクトップ（1180px以上）は左約67%・右約33%の2カラム。左上に配列図とプレビュー、左下に常時表示するジェスチャー3枚を並べ、右のコンボ欄を配列図へ直接隣接させる。コンボ欄はヘッダー下に追従し、見出し・対象切替を残して一覧部分だけを縦スクロールできる。配列図を見ながら全コンボを確認するためのスクロール設計とする。

1179px以下では配列→コンボ→ジェスチャーの順に縦積みし、コンボ欄の追従と内部スクロールを解除する。DOMもこの順にし、読み上げ・Tab操作と視覚上の順序を一致させる。狭い画面での横スクロールは配列図の領域だけに限定する。離れた位置からコンボを確認した場合には「配列図で確認」リンクも使える。

## コンポーネントと配色

| 要素 | 表現 |
| --- | --- |
| OS／コンボ対象 | 同幅のセグメント。選択中は独立したサーフェスとウェイトで示す |
| レイヤー | 主ラベル・起動方法の2段。現在のレイヤーは青と選択サーフェスで示す |
| 配列図 | 大きい文字＝短押し、下の小さい文字＝長押し。透過キーは点線。コンボ位置は強い塗りと輪郭を併用 |
| 通常／補助情報 | 主文字・補助文字のサイズとウェイト、余白で区別 |
| Bluetooth削除 | 通常の接続・切断から離し、レッド系のサーフェス・記号・明確な見出しで区別 |
| 初期設定 | ページ上部にOS設定とBluetoothへのテキストリンク |
| 開発者メモ | フッター直前の初期状態で閉じた開示領域 |

ライトはページ `#f5f5f7`、サーフェス `#ffffff`、アクセント `#0066cc`。ダークはページ `#171719`、サーフェス `#232326`、アクセント `#91c5ff`。色はCSS変数で意味ごとに管理し、OSの `prefers-color-scheme` に追従する。削除色も両テーマで読める濃さに調整する。外部フォント・CSSフレームワーク・本番用ライブラリは追加しない。

## インタラクションとアクセシビリティ

- 既存のID・`data-os`・`data-group`・`data-scope`・`data-combo`を維持する。生成元は `config/keymap.keymap`、`keymap-data.js` は手編集しない。
- コンボはマウスホバー／キーボードフォーカスで一時プレビュー、クリック・Enter・Spaceで固定。別の行をプレビューした後は固定状態に戻す。固定解除ボタン／Escで解除する。
- キーのプレビューではSVGを再生成せず、`data-position`を持つキーのクラスだけを更新する。塗りと輪郭のトランジションを保ち、配列の意味や番号を変えない。
- 選択状態は `aria-pressed`、レイヤー説明と選択結果は `aria-live`、図は `aria-label` で伝える。マウスだけの一時プレビューはライブ通知を抑える。
- OS・レイヤー・コンボ対象は通常のTab／Enter／Spaceに加え、左右矢印・Home・Endで操作できる。フォーカスリングは背景から見分けやすい3pxのアクセント色。
- キー位置番号は配列図のすぐ上で切替可能。開発者メモを開く必要はない。
- `prefers-reduced-motion` では切替アニメーションとトランジション、スムーズスクロールを止める。`forced-colors` ではキーの塗りと輪郭にシステム色を使う。
- 狭い画面では図解を拡大して縦に積み、タッチ入力ではセグメントや主要ナビゲーションの操作高を44px以上にする。

## 印刷／PDF

A4横向き、白背景の専用配色で出力する。画面がダークでも印刷用配色を優先する。操作用コントロールと閉じた補足を省き、配列・コンボ・ジェスチャー・ハードウェアガイドを残す。印刷は配列→コンボ→ジェスチャーの順に全幅で配置し、紙面の途中で大きな2カラムが分断されるのを避ける。印刷時はコンボ一覧の高さ制限と内部スクロールを解除して全件を出力する。

`beforeprint` で開発者の外側開示領域と全レイヤー配列を開く。使用中の12レイヤーはレイヤーごとに改ページする。技術メモは印刷しない。`afterprint` で元の開閉状態へ戻す。繰り返しの印刷イベントでも元の状態を上書きしない。

## 検証

WindowsのヘッドレスMicrosoft Edge（Playwright）で以下を確認した。

- 両OS×7レイヤーグループ、3種のジェスチャー表示、印刷用12レイヤーの生成。
- ホバー・フォーカス・固定・一時プレビューからの復帰・解除、対象レイヤーへの移動、Studio解除キー、位置番号切替。
- 矢印・Home・End・Enter・Escとフォーカス維持。
- デスクトップの67%／33%比率と配列・コンボの上端一致、タブレット以下の配列→コンボ→ジェスチャー順、DOM順の一致。
- 1440／1280／1024／800／650／390／320px × ライト／ダーク × 両OS × 基本／接続／記号の3グループ、計84条件でページ全体の横はみ出しがないこと。
- axe-coreのWCAG A／AA自動検査でライト／ダークとも検出違反なし。これは自動検査の範囲であり、支援技術による手動検証を含まない。
- 開発者メモへのリンクで開示されること、開閉操作、動きを減らす設定、印刷時の白背景と全レイヤー表示、印刷後の開閉状態復元。
- 右カラム内のホイールスクロールと追従、実際のタッチモードでの選択、44pxのセグメント操作高。
- 印刷ボタンの呼び出しとPDFを確認。この配列の15コンボ／全配列の24コンボ（Mac表示）および全12レイヤーが出力され、先頭の空白ページやページ外の文字がないことを確認。
- JavaScript実行エラーなし。生成処理と `git diff --check` を実行。

今回の変更は操作ガイドの表示と操作に限る。ファームウェアの実機動作確認とは分けて扱う。
